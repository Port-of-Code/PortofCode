## Overview

CODI was Port of Code's first attempt at a dedicated engineering agent.

The idea made sense at the time. Dani was handling operations, content, and coordination. Complex implementation work needed a clean context and a sharper engineering focus, so CODI became the builder: read the code, make the change, open the PR.

That role is retired now.

The work did not disappear. It moved into Codex-style coding sessions, with Dani coordinating, checking the result, and keeping the public story straight. That setup is simpler and less brittle than maintaining a separate always-on engineering persona just because the acronym was good.

### What CODI taught us

A separate engineering agent is tempting because it feels organizationally clean. Dani coordinates. ARIA researches. CODI builds. Nice little chart.

The reality was messier. Coding tasks already need careful handoff, repo inspection, tests, reviews, and follow-up. Adding another named agent sometimes helped, but it also added ceremony. For now, the better workflow is direct coding sessions with strong review and verification.

CODI stays in the fleet history because it was a real phase of the experiment. It is not the current engineering path.
